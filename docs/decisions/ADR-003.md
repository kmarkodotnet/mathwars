# ADR-003 — Hibrid teszt-stack: Unity Test Framework + tükör .NET solution

Státusz: ELFOGADVA · Dátum: 2026-11-16 · Döntéshozó: felhasználó (architect dokumentálja)

## Kontextus

A spec 17.1 legalább **10 000 seedelt** generált feladat invariáns-ellenőrzését írja elő, a
2. és 13. szakasz pedig Unity-független matematikai motort. Az Unity Test Runner indítása
(`-runTests -batchmode`) 40–120 másodperc hidegen, és telepített Unity Editort igényel —
ami a 6000.3 telepítéséig (ADR-001) nem is áll rendelkezésre. Forrásfájl-duplikálás tilos,
mert a két másolat azonnal divergálna.

## Döntés

**Egyetlen forráshely, két build-út.**

1. A Core, MathEngine, GameLogic, Analytics forrásai kizárólag a
   `Assets/_Project/Scripts/<Réteg>/` alatt élnek, `noEngineReferences: true` asmdef-fel.
2. A `tests/` .NET 9 solution projektjei **`Compile Include`-dal linkelik** ugyanezeket a
   fájlokat (`<Compile Include="..\..\game\Assets\_Project\Scripts\Core\**\*.cs" />`), és
   ugyanígy linkelik az EditMode teszteket.
3. **Duplikált forrásfájl TILOS.**
4. Következmény-szabály: **az EditMode tesztkód nem hivatkozhat `UnityEngine` típusra**
   (sem `UnityEngine.Random`, sem `Vector3`, sem `Debug.Log`). Unity-specifikus teszt
   kizárólag PlayMode-ban él, azt a `tests/` nem linkeli.
5. A `noEngineReferences: true` flag gépileg kikényszeríti a Unity-mentességet: aki
   `using UnityEngine;`-t ír a Core-ba, az az Editorban fordítási hibát kap.

## Alternatívák

| Alternatíva | Elvetés oka |
|---|---|
| Csak Unity Test Runner | lassú iteráció, Editor-függés, a 10 000-es fuzz-teszt fejlesztés közben használhatatlan |
| Csak .NET solution, Unity-ban nincs teszt | a PlayMode-integráció (harc + matek együtt fut) nem ellenőrizhető; spec 2. szakasz előírja az UTF-et |
| Külön NuGet csomagba szervezett motor, a Unity package-ként fogyasztja | verziózási és csomagolási overhead egy egyszemélyes projektre; a lépésenkénti debug körülményes |
| Symlink / fájlmásolás build-lépésben | platformfüggő, Windowsön adminjog kell, a Git kezelése törékeny |

## Következmények

- **Pozitív:** `dotnet test` másodpercek alatt lefut a MathEngine fuzz-tesztekre, Unity
  nélkül; CI-ban a gyors kapu előbb bukik, mint a lassú Unity-kapu.
- **Negatív:** az EditMode tesztek `UnityEngine`-mentessége extra fegyelem; a code-reviewer
  explicit ellenőrzi.
- A `tests/` projektek `LangVersion` és `nullable` beállításának meg kell egyeznie azzal,
  amit az Unity 6.3 (C# 9 / .NET Standard 2.1 profil) fordít — ezért a motorkódban nem
  használható olyan nyelvi elem, amit az Unity nem fordít le. **Gyakorlati szabály: C# 9
  nyelvi szint a célkeresztben** (`record`, `init`, target-typed `new` OK; `required`,
  `file`-scoped type NEM).
- A kész-definíció része: `dotnet test` zöld ÉS az Unity Editor hibamentesen fordít.
