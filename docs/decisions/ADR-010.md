# ADR-010 — `SkillMasteryLevel`: diszkrét készség-fokozatok a nyers `MasteryEstimate` helyett

Státusz: ELFOGADVA · Dátum: 2026-11-16 · Döntéshozó: architect
Érinti: `contracts/core-domain.md` 4., `contracts/math-engine.md` 6., `contracts/game-logic.md` 9.,
`contracts/scriptable-object-schema.md` 9., `balance/worlds.md` 3., `balance/difficulty-model.md` 2.

## Kontextus

A `SkillProfile` eredetileg csak folytonos jellemzőket adott:
`MasteryEstimate` (0.0–1.0), `Confidence` (0.0–1.0), plusz egy `MasteredSkills` listát
(`MasteryEstimate >= 0.8 && Confidence >= 0.6`).

Ugyanakkor három, egymástól független helyen **diszkrét fokozatokra** van szükség:

1. **Generátor-kapu (spec 7.2, 619–621. sor):** csak olyan készséget használhat a generátor,
   amely a profilban legalább „`Introduced`” állapotban van. A `difficulty-model.md` 2.
   szó szerint ezt a szót használja.
2. **Világ-feloldás (`worlds.md` 3.):** W4 feltétele `Multiplication: Practiced`,
   W6-é `OperatorPrecedence: Practiced`, W7-é `Mastered`. Három különböző szint kell.
3. **Parent Dashboard (spec 11.3):** a szülőnek nem 0,62-es lebegőpontos számot, hanem
   érthető fokozatot kell látnia.

A kontrakt eddig nem ismerte ezeket a szavakat, így minden hívó a saját küszöbét írta volna
be (`estimate > 0.5`, `> 0.45`, `>= 0.6` …) — ez pontosan az a „kódba égetett mágikus szám”,
amit a spec 16. tilt, és garantált inkonzisztencia a párhuzamos agentek között.

## Döntés

Bevezetünk egy diszkrét enumot a `MathHorde.Core.Skills` névtérben:

```csharp
public enum SkillMasteryLevel { Locked = 0, Introduced = 1, Practiced = 2, Mastered = 3 }
```

| Fokozat | Jelentés | Küszöb (`SkillPrerequisiteSO`-ból) |
|---|---|---|
| `Locked` | az előfeltételei sem teljesülnek; a generátor **nem** adhat ilyen feladatot | — |
| `Introduced` | az előfeltételek rendben, a generátor adhat ilyen feladatot (`Attempts == 0` is ide tartozik) | — |
| `Practiced` | `Attempts >= MinAttemptsForMastery / 2` (alap 4) **és** `MasteryEstimate >= PracticedThreshold` (alap 0.5) | `PracticedThreshold` |
| `Mastered` | `MasteryEstimate >= MasteryThreshold` (alap 0.8) **és** `Confidence >= 0.6` | `MasteryThreshold`, `MinAttemptsForMastery` |

### Kötelező szabályok

1. **Egyetlen lekérdezési út:** `SkillProfile.GetMasteryLevel(SkillTag)`. A hívó oldalon
   (MathEngine, GameLogic, Presentation) `MasteryEstimate`-tel való **közvetlen összehasonlítás
   TILOS** — a code-reviewer ellenőrzi. A nyers float megmarad az adatmodellben (naplózás,
   dashboard-grafikon), de döntést nem hoz rá senki a `SkillProfile`-on kívül.
2. **A küszöbök konfigurációból jönnek:** `SkillPrerequisiteSO` (`MasteryThreshold`,
   `PracticedThreshold`, `MinAttemptsForMastery`, `MinSamplesForConfidence`,
   `PrerequisiteMinLevel`). Ez az asset a küszöbök **egyetlen** forrása.
3. **Monotonitás:** a fokozatok sorrendezettek (`Locked < Introduced < Practiced < Mastered`),
   így a feltételek `>=` összehasonlítással írhatók
   (`GetMasteryLevel(tag) >= SkillMasteryLevel.Introduced`).
4. **„Soha nem elég egyetlen helyes válasz”** (spec 8.): a `Mastered` fokozat `Confidence`
   feltétele miatt legalább `MinSamplesForConfidence` (alap 8) mintát igényel. Ezt az enum
   küszöbei garantálják, nem a hívó fegyelme.
5. **Előfeltétel-ellenőrzés:** `ISkillClassifier.IsEligible(skill, profile)` minden
   előfeltételre `profile.GetMasteryLevel(prereq) >= SkillPrerequisiteSO.PrerequisiteMinLevel`
   (alap `Practiced`) vizsgálatot végez.

## Alternatívák

| Alternatíva | Elvetés oka |
|---|---|
| Marad a nyers `MasteryEstimate`, minden hívó maga dönt | 3+ hívó, 3+ különböző küszöb, mind kódba égetve (spec 16. sértés); a `worlds.md` `Practiced` feltételei nem reprodukálhatók |
| Csak `bool IsUnlocked` / `bool IsMastered` | a `worlds.md` három különböző szintet kér (`Introduced` / `Practiced` / `Mastered`); két boolean három szintet csak implicit konvencióval ad |
| Finomabb skála (5–7 fokozat, pl. CEFR-szerű) | nincs olyan termékfunkció, amely 4-nél több szintet használna; a `Confidence` szórása 8–30 minta között nem indokol finomabb felbontást |
| A fokozat perzisztálása a profilban (nem származtatott) | a küszöb-változás (balance-tuning) után a mentett fokozatok inkonzisztensek lennének a nyers adattal; származtatva a mentés mindig újraértelmezhető |

## Következmények

- **Pozitív:** a generátor-kapu, a világ-feloldás és a szülői felület **ugyanazt** a
  tudásfogalmat használja; a küszöbök balance-tuning során kódmódosítás nélkül állíthatók;
  a `worlds.md` feloldási feltételei végre leírhatók a kontrakt nyelvén.
- **Negatív:** a `SkillProfile` egy származtatott számítást kap, amelynek konfigurációra
  (`SkillPrerequisiteSO` küszöbök) van szüksége — a `SkillProfile` konstrukciójakor ezeket
  át kell adni (Core nem olvas SO-t, ezért egy egyszerű `SkillMasteryThresholds`
  value-objectként, ADR-003 szerint).
- **Fázis:** a `SkillMasteryLevel` enum és a `GetMasteryLevel` **F4** (Készségprofil és
  adaptáció) feladata; F1–F3-ban a `SkillProfile` opcionális (`null`) a generátor-kérésben,
  és a kapu „minden `Introduced`” fallbackkel működik — de a **kontrakt már most rögzített**,
  hogy a dev agent ne találjon ki saját küszöböket.
