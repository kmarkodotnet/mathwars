# ADR-002 — Repó-elrendezés: a `game/` repó a termék, a gyár kívül marad

Státusz: ELFOGADVA · Dátum: 2026-11-16 · Döntéshozó: felhasználó
Revízió: 2026-11-16 — az eredeti változat a gyárat és a terméket egyetlen
repóban képzelte el (`game/` + `tests/` + `docs/` a munkaterület gyökerében).
A felhasználó döntése alapján a **termék önálló git repó**, a gyártási
infrastruktúra pedig a repón kívül marad. Ez az ADR a hatályos állapotot írja le.

## Kontextus

A `math-horde.md` 20. szakasza a repó **gyökerében** várja a Unity projektet és a
kötelező dokumentumokat (`README.md`, `ARCHITECTURE.md`, `GAME_DESIGN.md`,
`TESTING.md`). Ugyanakkor a gyártást egy Claude Code-alapú agent-gyár végzi, amelynek
saját konfigurációja (`.claude/`), szkriptjei, telemetriája és folyamat-melléktermékei
(bug-riportok, review-k, retrospektívák) vannak. Ezek nem a termék részei, és nem
kerülhetnek a nyilvános termék-repóba.

A felhasználó a git repót a `game/` mappában hozta létre, `github.com/kmarkodotnet/mathwars`
remote-tal.

## Döntés

```
<munkaterület gyökere>        = GYÁR (nincs verziókövetés alatt)
  CLAUDE.md, README.md        – a gyár szabályai, belépési pont
  math-horde.md               – a jóváhagyott termékspecifikáció
  .claude/                    – agentek, parancsok, skillek
  scripts/                    – worktree- és telemetria-kezelés
  factory-metrics/            – futási telemetria
  factory-docs/               – folyamat-nyomok: bugs/, reviews/, incidents/,
                                retros/, ops-inbox/, requirements/, templates/
  worktrees/                  – a párhuzamos feature-worktree-k (generált)
  game/                       = TERMÉK (git repó → GitHub: mathwars)
    Assets/, Packages/, ProjectSettings/   – a Unity 6.3 projekt
    tests/                    – tükör .NET solution (ADR-003)
    docs/                     – ARCHITECTURE.md, GAME_DESIGN.md, TESTING.md,
                                DELIVERY.md, IMPLEMENTATION_STATUS.md,
                                ANDROID_BUILD.md, backlog.md, contracts/,
                                decisions/, balance/
    README.md, .gitignore
```

A spec 20. szakasza **betű szerint teljesül**: a termék repójának gyökerében ott van a
Unity projekt, és a `docs/` alatt minden kötelező dokumentum, amire a repó `README.md`-je
közvetlenül hivatkozik.

**Útvonal-konvenció (két kontextus):**
- A termék-dokumentáció (`docs/**`) a repó gyökeréhez relatív utakat használ:
  `Assets/_Project/Scripts/...`, `docs/...`, `tests/...`.
- A gyár konfigurációja (`.claude/`, `CLAUDE.md`, szkriptek) a munkaterület gyökeréhez
  relatív, ezért ott minden termék-útvonal `game/` prefixet kap.

## Alternatívák

| Alternatíva | Elvetés oka |
|---|---|
| Egyetlen repó a munkaterület gyökerében (a gyár is verziózva) | A gyárkonfiguráció és a folyamat-melléktermékek bekerülnének a nyilvános termék-repóba; a felhasználó a repót a `game/` alatt hozta létre |
| Két külön repó (termék + gyár) | A kontrakt és a kód külön verziózva divergálhat, egy feature nem commitolható atomian |
| A `docs/` a gyárnál marad | A spec 20. szakasza kötelezően a termék-repóba kéri a dokumentumokat; GitHubon a repó önmagában nem lenne értelmezhető |

## Következmények

- **Pozitív:** a GitHub repo pontosan a terméket tartalmazza — Unity projekt, tesztek,
  kötelező dokumentáció. A gyár cserélhető/újraépíthető a termék érintése nélkül.
- **Pozitív:** a `factory-docs/` a repón kívül van, így a bug-riportok és review-k nem
  okoznak merge-konfliktust a párhuzamos worktree-k között.
- **Negatív / vigyázat:** a gyárkonfiguráció (`.claude/`, `CLAUDE.md`) **nincs
  verziókövetés alatt**. Ebből következik, hogy a `factory-engineer` agent önfejlesztő
  hurka (módosítás külön `factory/*` ágon, code-review kapuval) jelen állapotban nem
  végrehajtható — a gyár módosítása csak felhasználói felügyelettel, közvetlenül
  történhet. Ha az önfejlesztő hurok kell, a gyökérhez külön repó inicializálandó.
- Minden git művelet a `game/` repóra irányul: `git -C game ...`. A worktree-k a
  `worktrees/<feature>` mappába kerülnek (`scripts/new-feature.sh`).
- Az Android build kimenete: `Builds/` (gitignore-olt), a build-útmutató a
  `docs/ANDROID_BUILD.md`-ben.
